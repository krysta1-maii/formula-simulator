## 1. 审查范围与结论

本次审查覆盖静力求解、悬架运动学、六自由度动力学、Three.js 场景、参数与遥测界面、单文件构建、Node 测试和浏览器测试。重点检查物理状态定义、坐标系一致性、求解器收敛、低速接触、帧率边界、几何重建和界面可访问性。

项目作为阶段二的小姿态悬架动力学可视化原型，具有较好的完成度：离线单文件分发清晰，设计文档详细，物理与渲染共用机构几何，测试覆盖静力、动力学、机构闭合和真实浏览器交互。

当前版本不宜直接扩展为阶段三的完整车辆动力学底座。审查中复现了若干现有测试未覆盖的问题，其中摇臂求解的收敛缺口会在合法滑块参数下产生数十 kN 的异常阻尼力。建议先修正动力学内核和求解器，再通过显式模块、不可变参数和版本化快照降低耦合。现有离线分发、视觉资产、文档和测试基础均可保留，不需要推倒重写。

本报告中的“高”“中”“低”表示修复优先级。高优先级问题会使物理解或关键交互在可达条件下产生错误；中优先级问题影响特定边界、状态一致性或性能；低优先级问题主要影响维护和工程健壮性。

## 3. 项目的主要优点

### 3.1 交付与文档

根目录的 [index.html](../index.html) 将 Three.js、样式和应用代码合并为自包含页面，双击即可离线运行。[构建脚本](../tools/build.mjs#L8-L31) 没有第三方构建依赖，当前生成物与源码一致。[README](../README.md) 和 [DESIGN](../DESIGN.md) 对坐标、模型边界、已知简化和后续阶段有较完整的说明。

### 3.2 机构几何与验证

[悬架求解器](../src/js/03-suspension.js) 为动力学和渲染提供共同的硬点与机构解。现有测试不仅检查数值有限，还覆盖杆件闭合、接地点共面、运动比、转向标定、可见弹簧长度与遥测一致性，具有明确的工程验证价值。

### 3.3 测试层次

项目同时具备 Node 核心测试、无头浏览器动态测试和相机交互测试。相比只验证页面能够打开，这些测试已经覆盖暂停/继续、脉冲、低附着滑移、重置、几何重建和相机预设，适合作为后续回归体系的基础。

## 4. 高优先级发现

### 4.1 摇臂求解未检查收敛，异常运动比会进入阻尼力计算

[suspRockerAngle](../src/js/03-suspension.js#L229-L247) 在迭代失败、导数异常或未闭合时仍直接返回角度，没有返回残差和成功状态。[suspSolveCorner](../src/js/03-suspension.js#L257-L296) 的 converged 只代表轮架三个约束收敛，没有包含推杆—摇臂闭合。高低行程探测同样只检查轮架求解结果。

随后，[simEvaluate](../src/js/05-body-dynamics.js#L241-L262) 接受由此得到的瞬时运动比并计算弹簧、阻尼力，导致非物理解直接进入力学链路。

本次使用界面允许范围内的参数进行俯仰脉冲实验：

| 参数 | 数值 |
| --- | ---: |
| mass | 600 kg |
| wheelRateF / wheelRateR | 50 / 50 N/mm |
| dampingF / dampingR | 0.05 / 0.05 |
| arbFront / arbRear | 0 / 0 |

实验结果如下：

| 观测量 | 结果 |
| --- | ---: |
| 瞬时运动比最小值 | -7.58 |
| 瞬时运动比最大值 | +7.35 |
| 左前阻尼力峰值 | +41.94 kN |
| 峰值处 solverConverged | true |
| 同工况页面动态自检 | 8/8 通过 |

默认参数没有触发这一峰值，因此该问题属于参数包线内的求解器缺陷。在一个俯仰 1.15° 的样本中，高行程探测的推杆闭合残差约为 3.59 mm，该解仍参与了运动比微分。

**修复建议：**

1. 让摇臂求解返回 rockerError、rockerConverged 和角度。
2. 将轮架、摇臂和运动比有限性合并为统一的角点求解状态。
3. 高低行程探测保持同一根分支，任何一个探测失败都不得计算数值运动比。
4. 对运动比做连续性及合理范围检查，失败时进入明确降级状态，不继续把异常值用于力计算。
5. 在遥测和 UI 中展示求解失败及残差，避免只显示有限性正常。

这是第一优先级，因为异常结果已经能够进入实际力学链路。

### 4.2 平动积分参考点不是质心，却遗漏旋转耦合项

[05-body-dynamics.js:206–211](../src/js/05-body-dynamics.js#L206-L211) 定义质心位置为：

> r_CG = state.position + R(q) · cgBody

因此 state.position 是车身设计参考点，不是质心。但 [05-body-dynamics.js:415–464](../src/js/05-body-dynamics.js#L415-L464) 直接把 F/m 积分成该参考点的加速度。

对于非质心参考点，正确关系为：

> a_CG = a_ref + α×r + ω×(ω×r)

当前实现遗漏切向和向心项。角速度为零的平衡测试无法暴露这一问题。

本次在关闭重力和悬挂反力的单元工况中，给车体 1 rad/s 的自由侧倾角速度。没有外力时质心应保持静止，1 秒后模型中的质心却漂移约 287.7 mm。

**修复建议：**优先把积分状态改为质心位置和质心速度，车身设计参考点通过 p = r_CG - R(q)c 推导。这样平动方程可直接保持 F = m·a_CG，也便于后续验证轮胎力、空气动力和动量。另一种方案是补齐参考点加速度耦合项，但实现和验证更复杂。

这项修正应在阶段三之前完成，否则高速旋转、驱动和转向会放大误差。

### 4.3 低速摩擦同时存在速度反转和无摩擦死区

[05-body-dynamics.js:324–371](../src/js/05-body-dynamics.js#L324-L371) 使用两个不同阈值：atRest 的速度阈值为 1e-4，接地点滑移速度只有大于 1e-3 才按速度方向施加动摩擦。

当水平路面的切向需求为零、速度位于两个阈值之间时，摩擦方向会变成零，但状态仍不满足 holding。独立复现中，给水平车体 vx = 0.0005 m/s 后，四轮摩擦力均为零；继续运行 2 秒，车辆仍保持该速度并标记为“滑移”。

较大初速度也有数值问题。默认水平路面、vx = 0.01 m/s 时，按初始摩擦能力估算约 0.728 ms 就应停下；当前一个 2 ms 子步后，速度直接变成 -0.01746 m/s，发生反向。

**修复建议：**建立明确的 HOLD / SLIP 状态转换，并基于摩擦冲量处理单步过零。如果本步动摩擦冲量会使滑移速度反向，应改为进入静态约束或受控归零，而不是继续施加原方向摩擦。状态转换需要同时考虑车体平动和接地点旋转滑移。

### 4.4 脉冲作用点混用车体系与路面系

脉冲偏移量在 [05-body-dynamics.js:178–192](../src/js/05-body-dynamics.js#L178-L192) 中按车体局部坐标定义，但 [05-body-dynamics.js:375–382](../src/js/05-body-dynamics.js#L375-L382) 直接计算 simCross(impulse.offset, impulse.force)，作用点没有先通过 R(q) 转到路面坐标。

实测车体横摆 90° 后，“俯仰脉冲”在车体坐标中实际产生约 5890 N·m 的侧倾力矩。

修复时应先计算 roadOffset = simQuatRotate(q, impulse.offset)，再用 roadOffset 与路面系力求叉乘。回归测试应比较有/无脉冲时的力矩差，而不是只观察姿态峰值。

### 4.5 力矩与可视化使用两套接地点

[05-body-dynamics.js:267–280](../src/js/05-body-dynamics.js#L267-L280) 使用 yaw-only 的设计轮位计算法向力矩、摩擦力矩和接触速度；[05-body-dynamics.js:588–603](../src/js/05-body-dynamics.js#L588-L603) 又另外计算完整姿态下的机构接地点。

在默认俯仰脉冲 60 ms 的正常 UI 工况中，两套接地点最大相差约 8.50 mm。该差异会影响力臂、滑移方向和轮载标注位置。姿态继续增大时，误差随之增大。

**修复建议：**每个角点只产生一次道路系接地点，让法向力矩、摩擦力矩、接触速度、遥测和可视化共同使用它。求解失败时的回退也应使用完整四元数，而不是退回 yaw-only 位置。

## 5. 中优先级发现

### 5.1 低帧率下静默丢失仿真时间

[simAdvance](../src/js/05-body-dynamics.js#L525-L535) 每帧最多执行 40 个 2 ms 子步，即最多推进 80 ms；达到上限后直接清空累加器。

| 渲染频率 | 相同 1 秒墙钟输入所推进的仿真时间 |
| ---: | ---: |
| 60 Hz | 1.000 s |
| 10 Hz | 0.800 s |
| 5 Hz | 0.400 s |

应用层还在 [40-app.js:414–430](../src/js/40-app.js#L414-L430) 把帧间隔截断到 50 ms，会进一步降低低帧率下的推进速度。

防螺旋保护本身合理，问题在于时间被静默丢弃，与 [README.md:162–164](../README.md#L162-L164) 的“掉帧后物理结果一致”表述不完全一致。建议明确选择慢动作或丢弃策略，保留 backlog/droppedTime 并在遥测中报告；若要求低帧率实时推进，需要重新匹配最大帧时长和最大子步数。

### 5.2 几何代际可以混用

[FSApp.setState](../src/js/40-app.js#L336-L346) 允许尺寸变化被 options.rebuild = false 覆盖。实测将轴距改为 3.90 m 后，旧硬点与新轮位混用，悬架杆长偏差达到 104.10 mm。

普通尺寸滑块会自动重建，因此该确定复现主要影响公开 API、测试和后续集成；等待节流重建期间也存在同类的短暂代际混用风险。

建议尺寸变化时强制重建，并给参考模型和 Three 场景增加 geometryRevision，只允许同代数据组合。等待重建时应显示上一套匹配模型，完成后原子替换。

### 5.3 周期遥测重复运行自检并重建 DOM

[refreshTelemetry](../src/js/30-ui.js#L676-L680) 每次都会重跑静态自检，[主循环](../src/js/40-app.js#L425-L434) 最高每 110 ms 调用一次该函数；[refreshChecks](../src/js/30-ui.js#L563-L649) 还会清空并重新创建检查项 DOM。

本次无头 Chrome/SwiftShader 环境中，一组静态自检约 11 ms，打开模态框时同步动态自检约 768 ms。这些数值只代表当前测试环境，但已经说明自检不适合放在周期遥测路径中。

建议按 setupRevision 缓存自检结果，参数未变化时只更新实时遥测；检查列表保留节点，仅写变化的文本和 class；动态自检改为显式按需执行，并考虑 Worker 或分片任务。

### 5.4 车辆重建没有释放独立材质

[disposeGroupChildren](../src/js/20-car.js#L175-L187) 只收集并 dispose 几何体。[buildCar](../src/js/22-car-dynamics.js#L1156-L1159) 每次尺寸重建都会调用它，而车身中存在多处独立材质创建，例如 [20-car.js:629](../src/js/20-car.js#L629)、[20-car.js:685](../src/js/20-car.js#L685) 和 [20-car.js:747](../src/js/20-car.js#L747)。

一次真实轴距重建的插桩结果为 387 次 BufferGeometry.dispose、0 次 Material.dispose。该结果确定说明材质生命周期没有正常结束；是否形成持续内存增长仍需长期堆/GPU 测量，不应直接夸大为已证实崩溃。

建议区分共享、缓存和实例资源，按所有权释放材质与纹理，并为整个场景提供统一销毁入口。

## 8. 重构建议

### 8.1 先稳定动力学内核

保留现有车身、车轮和机构渲染资产，主要改写 [05-body-dynamics.js](../src/js/05-body-dynamics.js) 以及 [03-suspension.js](../src/js/03-suspension.js) 的求解结果协议。

| 数据类型 | 建议职责 |
| --- | --- |
| Setup | 不可变用户参数，带 setupRevision |
| BodyState | 质心位置、质心速度、四元数和车体角速度 |
| CornerSolution | 轮架位姿、唯一接地点、线圈长度、摇臂残差和统一收敛状态 |
| ForceEvaluation | 合力、合力矩、接触状态和摩擦状态 |
| TelemetrySnapshot | UI 只读输出，携带 setupRevision 与 geometryRevision |

渲染层只消费快照，不反向写入物理角点、求解种子或硬点。显示开关、单位切换和截图也不应触发物理参考模型重建。

### 8.2 用显式模块替代隐式脚本拼接

当前 [build.mjs](../tools/build.mjs#L12-L21) 按文件名排序拼接脚本，模块之间依赖全局函数和数字前缀。轮胎、驱动和空气动力加入后，这种依赖方式会增加修改成本。

建议逐步改为 ES Modules，明确导入导出。构建时仍生成单文件 IIFE，保留双击离线运行的优点；可以使用开发期打包依赖，运行时继续零依赖。测试直接 import 核心模块，替代 [test-dynamics.mjs:13–20](../tools/test-dynamics.mjs#L13-L20) 的 new Function 和手工文件列表。

暂时不需要引入前端框架，也不必同时进行全面 TypeScript 迁移。先为核心状态和求解结果补 JSDoc 类型，能够更直接地降低接口歧义。

### 8.3 分离物理、遥测、自检和渲染调度

500 Hz 物理积分、3D 渲染、低频 DOM 遥测和验收自检应具有独立调度。自检由参数版本触发或按需执行，DOM 仅更新变化字段，静态页面可按 dirty flag 重绘。

尺寸重建采用原子替换：等待期间显示上一套匹配模型，完成后同时替换物理参考与场景，避免新轮位配旧硬点。共享几何、缓存材质和实例材质分别管理所有权，并提供完整 teardown。

## 9. 推荐实施顺序与回归测试

| 阶段 | 实施内容 | 必须新增的验证 |
| --- | --- | --- |
| 1 | 修复摇臂求解状态、运动比连续性和失败回退 | 推杆—摇臂独立残差、合法低刚度/低阻尼脉冲、运动比符号与连续性 |
| 2 | 改为质心积分，统一脉冲和接地点坐标 | 自由刚体解析轨迹、动量/能量不变量、90° 横摆脉冲、接地点与力矩独立重算 |
| 3 | 修复 HOLD / SLIP 和帧时间语义 | 低速停止、单步过零、坡面转水平后的重新驻车、10/12/30 Hz 与恢复帧 |

## 10. 最终结论

项目的离线交付、设计文档、机构几何和现有测试构成了良好的原型基础。当前主要风险集中在求解失败仍可进入力计算、非质心参考点积分、低速摩擦状态转换、坐标系混用，以及物理与场景的代际耦合。

建议保留现有视觉资产和分发方式，对动力学内核进行有针对性的修正，并以显式模块、不可变参数和版本化快照完成结构性重构。完成本报告中的高优先级修复及独立回归后，再进入轮胎、驱动和空气动力开发，可以降低后续调试成本并提高物理解的可信度。
